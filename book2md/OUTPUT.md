# 변환 결과물 규격

후속 처리(판례별 사례 정리, 목차별 요약)에 이 문서를 함께 넘긴다.
읽는 쪽이 무엇을 믿어도 되고 무엇을 의심해야 하는지 여기 적혀 있다.

## 폴더

```
민소출력/
├── 윤곽 민소법 기본서/     NNN_<논점번호><제목>.md   논점 단위
├── 윤곽 민소 사례집 상/    <그룹>_<주제>.md          문제 그룹(A~I) 단위
├── 윤곽 민소 사례집 하/    <그룹>_<주제>.md          문제 그룹(J~Q) 단위
└── _reports/              검증 리포트 (아래 §검증)
```

원본은 종이를 스캔한 그림 위에 OCR 글자가 얹힌 PDF다. 그래서 글자에는
OCR 오인식이 섞여 있고, **저자가 칠한 강조색은 쪽 그림의 픽셀에서 읽어 냈다.**

## 마크업이 뜻하는 것

| 표기 | 뜻 | 출처 |
|---|---|---|
| `# ~ ######` | 편·장·논점·로마숫자 제목 | 원문 조판 |
| `**N. 제목**` | 학설/判例/검토 같은 소항목 | 원문 조판 |
| `` `[일나시 나소시]` `` | **두문자** — 답안에 그대로 현출하는 암기 장치 | 원문 대괄호 |
| `==텍스트==` | **저자가 색으로 칠한 부분** — 답안 현출용 알맹이 | 쪽 그림 픽셀 |
| `**텍스트**` (문장 속) | 검정 볼드 | 글꼴 속성 |
| `74다1557*` | 사건번호 + **중요 판례 표시** | 원문 별표 |
| `[^264]` / `[^264]: …` | 각주 참조 / 각주 본문 | 하단 각주 |
| `> ### ☑ 제목` | 보너스 논점 박스 — 목차 밖이지만 꼭 짚는 것 | 테두리 박스 |
| `` `(11)` `` | 변리사시험 기출연도 (2011년) | 제목 뒤 괄호 |
| `` `2.5` `` | 배점 (사례집) | 제목 뒤 숫자 |
| `> ` 인용 | 사례집 **문제 지문** — 판례 사실관계의 유일한 출처 | 테두리 박스 |

## 프론트매터

```yaml
---
source: 기본서
chapter: "046 일부청구"
sections: ["I. 의의", "IV. 시효중단", "V. 기판력"]
exam_years: [2011, 2022]        # 기출연도
outline: ["의의", "소송물", "시효중단"]   # 논점 윤곽 띠
cases:                          # 이 파일에 나온 판례
  - id: "91다43695"
    label: "청구확장 취지 명백히 표시"   # 쟁점명. 사건번호만으로는 뭔지 모른다
    standard: true                       # 별표 = 중요 판례
bonus_topics: ["실제로 청구취지 확장하지 않은 부분의 취급"]
mnemonics: ["일나시 나소시", "종확나시"]
articles: ["제265조", "제218조 제1항"]   # 인용된 조문. 두문자와 섞이지 않는다
parser: pymupdf
validation: WARN
---
```

`cases` 배열이 본문 사건번호와 일치하는지는 검증이 확인한다. **판례 누락
검사에 이 배열을 쓰라.**

`mnemonics` 에는 조문번호가 섞이지 않는다. 조문은 `articles` 로 따로 나간다.
`sections` 는 실제 헤딩이고, `outline` 은 저자가 첫 줄에 늘어놓은 논점 띠다.
둘이 어긋나면 절 하나가 헤딩으로 안 선 것이라 검증이 FAIL 로 잡는다.

## 구조 표시가 빠진 곳이 있다

절 제목이 `####` 를 못 달고 **본문 문단으로 들어가 있는 곳**이 논점 열댓 군데
있다. OCR 이 절 번호 자리를 뭉개 놓은 자리다(`I.` 이 `仁j`, `।`, `H`, `口` 로).

**글자는 하나도 안 잃었다.** 제목 줄이 사라진 것이 아니라 헤딩으로 안 잡혔을
뿐이다. 그러니 `####` 를 세어 절을 나누지 말고 **본문을 읽어라.** 어느 논점에
어떤 절이 있어야 하는지는 프론트매터 `outline` 이 알려 준다 — 그것이 저자가
논점 첫 줄에 적어 둔 목록이다. `sections`(실제 헤딩)와 `outline` 이 어긋나면
그 절은 문단 속에 있다.

어느 파일인지는 `_reports/warnings-*.md` 의 「5.7 목차」 항목에 다 적혀 있다.

## 강조(`==`)에 대하여

`==` 는 **제목·논점 윤곽 띠·두문자**에만 붙는다. 본문 판시의 강조 범위는
프로그램이 표시하지 않는다 — 이 교재의 본문 강조는 색이 아니라 굵은 글씨이고,
스캔본이라 굵기를 확실히 가릴 수 없기 때문이다. **강조 범위는 이 단계에서
판단할 것.** `==` 가 없다고 원문에 강조가 없는 것이 아니다.

## 믿어도 되는 것

- 사건번호 990건, 별표(중요 판례) 표시, 각주 본문 765개가 원본과 대조해 통과했다.
- 두문자 안쪽 글자는 **한 글자도 고치지 않았다.**
- 판시 문언을 요약·재구성하지 않았다. 한자(甲乙判例)도 그대로다.

## 의심해야 하는 것

| 무엇 | 얼마나 (기본서) | 어디 |
|---|---|---|
| 절 제목이 헤딩 대신 문단으로 (**글자는 있음**) | 논점 15곳 | `warnings-*.md` 「5.7 목차」 |
| 각주가 본문 참조를 못 이었다 (**각주 본문은 살아 있음**) | 73 / 743 | 〃 「5.6 각주」 |
| `정구`→`청구` 류 OCR 오인식 — **자동 치환하지 않았다** | 4건 | 〃 「4.6 추출검수」 |
| 사건번호 안이 깨져 정규식에 안 걸린 것 (`＜94=1840*)`) | 몇 건 | — |
| 낱말 사이 공백이 어긋난 곳 (`알수 없어`, `1 회적`) | 곳곳 | — |
| 쪽 머리말 잔해가 본문에 남은 곳 (`O과 己厂—I`) | 드묾 | `removed_lines.md` 반대편 |

실제 숫자는 `_reports/validation-*.md` 의 집계를 보라. 위 표는 마지막 전 범위
변환 기준이다.

띄어쓰기와 사소한 OCR 오타는 **일부러 고치지 않았다.** 맞춤법 교정을 켜면
두문자와 법률용어가 먼저 망가진다.

## 아직 사람이 결정하지 않은 것

`_reports/crosscheck-*.md` 에 **기본서와 사례집의 두문자 불일치**가 양쪽 원문과
함께 나란히 놓여 있다. 예: 기본서 `[확객시전]` vs 사례집 `[확객시젠]`.

**어느 쪽이 옳은지 프로그램은 정하지 않았다.** 후속 처리에서 두문자를 답안에
쓸 때는 이 목록을 먼저 확인할 것.

## 검증 리포트

| 파일 | 내용 |
|---|---|
| `validation-<파일>.md` | 판정과 집계 |
| `warnings-<파일>.md` | 사람이 확인할 지점 (앞뒤 30자 포함) |
| `caselist-<파일>.txt` | 사건번호 전수 + 출현 위치 |
| `mnemonics-<파일>.txt` | 두문자 전수 |
| `crosscheck-*.md` | 기본서↔사례집 두문자 대조 |
| `mnemonic_conflicts-*.md` | 두문자 결정표 (사람이 표시 → `apply-decisions`) |
| `removed_lines.md` | 버린 줄 전부 — 본문이 섞였는지 확인용 |
| `emphasis_check/` | 색을 못 읽은 쪽의 표준판례 판시 그림 (있을 때만) |
| `palette-<파일>.md` | 색상 팔레트 |
| `diagnosis-<파일>.md` | 원본 PDF 진단 |

`_work/<파일>/02_changes.jsonl` 에 **정규화가 손댄 자리가 전부** 남아 있다
(`＜`→`(` 복원, 두문자 괄호 복구, 날짜 표준화, 사람이 지정한 정정).
무엇이 어떻게 바뀌었는지 되짚을 수 있다.

## mapping.yaml — 어느 절이 어느 문제로 나왔나

`mapping build` 로 따로 만든다. 기본서 절과 사례집 문제를 잇는 표다.

```yaml
- textbook:
    chapter: "046 일부청구"
    section: "IV. 시효중단"
    file: "output/기본서/45_046일부청구.md"
  casebook:
    - id: "E-5"
      title: "일부청구-시효중단"
      points: 10          # 문제 총점
      section_points: 4   # 이 절에 걸린 답안 항목의 배점
      points_sum: 10      # 답안 배점의 합 — points 와 다르면 오인식 신호
      role: primary
  evidence:
    title_keyword: ["시효중단"]
    shared_cases: ["2019다223723", "2018다44114"]
    shared_mnemonics: ["일나시 나소시"]
    near_mnemonics: ["확객시전 ↔ 확객시젠"]   # 한 글자 차이 — 아직 확정 안 됨
  score: 3
  confirmed: false
```

**`confirmed: true` 인 것만 쓸 것.** `score: 3` 도, `mappings` 에 올라 있는
것도 그 자체로는 승인이 아니다. `candidates` 는 근거가 하나뿐이라 더 약하다.

`role` 은 배점으로 가른 것이다. `primary` 는 그 절이 문제의 주 논점,
`composite` 는 다른 논점과 묶여 나온 것, `incidental` 은 스치듯 언급된 것이라
노트에 안 써도 된다. **배점을 못 읽었을 때도 `composite`** 이 되므로,
`section_points: null` 이면 역할이 실제로 판정된 것이 아니다.

`near_mnemonics` 는 한 글자 차이라 같은 것으로 **간주**한 두문자다. 어느 쪽이
옳은지는 정해지지 않았다 — `mnemonic_conflicts-*.md` 를 함께 볼 것.
