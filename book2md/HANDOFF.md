# 다음 교재로 넘길 때 — 인수인계

민사소송법 교재로 만든 파이프라인을 다른 교재(특허법 등)에 이어 쓰기 위한 문서다.
**새 세션은 이 파일부터 읽으면 된다.**

프로그램은 새로 만들지 않는다. `book2md` 는 교재를 가리지 않게 만들어 두었고(§9),
교재마다 다른 것은 전부 `config.yaml` 에 있다. 특허법용 설정을 따로 두고
`--config` 로 지정한다.

```bat
copy config.yaml config-patent.yaml
convert --config config-patent.yaml diagnose "특허법 PDF 폴더"
```

---

## 전체 파이프라인

```
[1] PDF → 마크다운          convert diagnose → convert all
[2] 절 제목 점검 → 고치기    convert audit-sections → config 손질 → 재변환
[3] 기본서 ↔ 사례집 매핑     mapping build → review → confirm
[4] 노트 생성               Claude 가 SKILL.md 를 읽고 md → md
```

[4]는 코드가 아니다. 스킬 문서를 읽은 Claude 가 하는 일이다. 이 리포는 [1]~[3]까지다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `convert diagnose <PDF폴더>` | 사전 진단. **이걸 건너뛰면 run 이 막힌다** |
| `convert all <PDF폴더> --out <출력>` | 진단→변환→검증→교차검증 한 번에 |
| `convert audit-sections <출력> --out audit.md` | 절 제목 전수 점검. 재변환 없이 변환물만 읽는다 |
| `convert probe <PDF> --lines --pages 170-173` | 줄마다 무엇으로 읽혔는지. 헤딩이 안 잡힐 때 |
| `convert apply-decisions <결정표>` | 두문자 결정표에 표시한 대로 config 를 고친다 |
| `mapping build <출력> -o mapping.yaml --report dbg.md` | 기본서↔사례집 매핑 |
| `mapping review / confirm / validate` | 승인 대기 목록 · 승인 · 검증 |

두 도구 다 **아무것도 자동 승인하지 않는다.** 사람 판단이 필요한 자리(두문자 결정,
매핑 승인, 사건번호 육안 검수)는 리포트로 넘긴다.

## 교재가 바뀌면 손대는 곳

`config.yaml` 에서 이 항목들만 보면 된다.

| 항목 | 무엇 |
|---|---|
| `preserve.case_suffixes` / `known_suffixes` | 사건번호 부호. 특허는 `후`(대법원)·`허`(특허법원)가 이미 들어 있다 |
| `preserve.year_min` / `year_max` | 4자리 연도 범위 |
| `legend.outline.keywords` | 논점 윤곽 띠에 나오는 낱말. **교재마다 다르다** |
| `legend.sidenote.pattern` | 옆번호 모양 (`sE-8` 꼴) |
| `running.never_heading` | 책 제목. 머리말이 절 제목이 되는 것을 막는다 |
| `profiles.<이름>.headings` | 절 번호 모양 (`I.` `1.` `제N절`) |
| `profiles.<이름>.label` | 프론트매터 `source:` 에 적히는 이름. 매핑이 이걸로 기본서/사례집을 가른다 |
| `normalize.roman_heads` | 로마자 번호 오인식 표 (`I` ← `l` `|` `।` `仁j`) |
| `normalize.corrections` | **사람이 확인한 정정만.** 프로그램은 스스로 고치지 않는다 |

절대 건드리지 않는 것: §4.8 금지사항 — 맞춤법 자동 교정, 문장 재구성·요약,
판시 문언 수정, 한자를 한글로 변환. 정정은 `corrections:` 로만 한다.

## 이번에 겪은 함정 — 다음 책에서도 똑같이 겪는다

### 목차 띠가 모든 것의 근거다

논점 첫 줄의 `◎ 의의-내용-예외-효과` 띠는 **뭉개진 절 제목 복구·검증·절 점검
셋 모두의 근거**다. 띠 하나를 못 읽으면 그 논점의 절이 줄줄이 묻힌다.

`convert audit-sections` 의 맨 윗줄 `목차 띠를 읽은 파일 N/M개` 를 **가장 먼저**
본다. 낮으면 다른 숫자는 볼 필요가 없다.

실측: 띠 9개를 못 읽은 이유가 `keywords` 목록이었다. `◎ 개시–진행–종결–재개`
가 넷 다 목록에 없어서 띠가 아니라고 판정했다. 지금은 표지(`◎ & ※`)가 있고
토막이 셋 이상이면 낱말을 요구하지 않는다. 표지가 없는 교재라면 `keywords` 를
그 교재의 말로 새로 채워야 한다.

### 반복 횟수로 머리말을 판정하지 말 것

`I. 의의 및 취지` 는 논점이 135개면 77곳에 나온다. 반복은 정상 절의 성질이다.
러닝 헤더는 **책 제목 문자열**로 가른다 (`running.never_heading`).

### 목차 항목 하나를 여러 절이 나눠 쓰는 것은 정상

`요건-당사자 동일`, `요건-소송물 동일`, `요건-권리보호이익` 셋이 띠의 `요건`
하나에 대응한다. 번호가 성한 절끼리는 서로 막지 않는다. 번호가 뭉개진 줄이
뒤늦게 같은 항목을 집을 때만 가짜다.

### 띠와 절은 이름이 다르다

띠는 축약형, 절은 완전형이다 — `협의소송자료` ↔ `III. 협의의 소송자료 준별과 완화`.
완전 일치로 대조하면 진짜 절이 「짝 없음」으로 나온다.

### 매핑은 답안 목차가 주력이다

지침이 정한 세 근거(제목 키워드·사건번호·두문자)만으로는 실물에서 판정이 안 선다.
사례집은 판시를 요지로만 압축해 실어 사건번호가 문제 323개 중 294개가 0건이었다.

대신 **사례집 답안 목차가 기본서 절 구조를 그대로 옮겨 적는다.**
`E-2 > 3. 일부청구 후 잔부청구 중복소제기 해당 여부` ↔ `III. 중복소제기`.
이것만으로 사람이 손으로 확인한 정답지 8건이 배점까지 그대로 재현됐다.

- 답안 목차 대조는 **장이 맞은 안에서만** 한다. 안 그러면 절 500 × 문제 300 이
  이름만 겹쳐 다 이어진다 (실측 12,177쌍).
- `의의`·`내용`·`요건`·`효과` 같은 짧은 절 이름은 어느 장에나 있어 뺀다.
- 총점은 제목이 아니라 **문제 지문 끝**에 있다 — `…설명하시오. (14점)`.
- `role` 의 25% 문턱 분모는 총점이 아니라 **읽은 배점의 합**이다. 총점을 쓰면
  배점을 덜 읽었을 때 role 이 사안 적합도가 아니라 OCR 성공률을 재게 된다.
- 사례집 앞머리 **목차 쪽**을 문제로 읽지 않는다. 같은 번호가 두 번 실리면
  진짜 문제의 사건번호·두문자가 빈 껍데기에 가려진다.

### 색상 추출은 껐다

스캔본은 OCR 글자가 전부 검정이라 색이 그림 픽셀에만 남는다. 한 번 켜 봤으나
본문 강조는 **굵은 검정**이고 청색은 제목·두문자뿐이어서, 임계값을 낮추면 가짜
강조가 만들어졌다. 지금은 `preserve.color.bold_from_image: false`. 강조 범위는
노트 단계에서 AI 가 직접 판단한다 (`OUTPUT.md` §5 참조).

### 일하는 순서

한 번에 전 범위를 돌리지 않는다. **하나 먼저 → 검증 → 규칙 보완 → 전체.**
그리고 **고치기 전에 세기부터** 한다. 표본 몇 줄로 진단해 고치면 그 몇 줄에만
맞춘 수선이 된다. 실측으로 99건 중 60건이 점검기 자신의 오탐이었다.

## 특허법에서 달라질 만한 곳

미리 확인할 것들. 진단(`convert diagnose`)이 대부분 알려준다.

- **사건번호**: `2019후10500`(대법원), `2020허1234`(특허법원). 부호는 이미
  등록돼 있으나 일련번호가 5자리인 것이 많다 — `convert probe <PDF>` 로 확인.
- **심결·심판번호**: `2019당123`, `2020원456` 같은 것이 있으면
  `case_suffixes` 에 추가해야 한다. **길이순으로 정렬되므로 순서는 상관없다.**
- **조문 인용**: 특허법·실용신안법·디자인보호법이 섞인다. `article_units` 와
  `article_cite` 가 `제N조의N` 을 받는지 확인.
- **사례집 유무**: 사례집이 없으면 [3] 매핑 단계 자체가 없다. 기본서만으로
  노트를 만들면 「사건의 전말」이 각주와 `[예시 사안]` 으로 채워진다.
- **논점 윤곽 띠**: 같은 출판사 판형이면 그대로 간다. 아니면 `legend.outline` 을
  새 교재에 맞춰야 하고, 그게 이 파이프라인에서 제일 중요한 설정이다.

## 새 세션 첫 명령

```bat
cd C:\MyCode\pdf2md\book2md
git pull

copy config.yaml config-patent.yaml
convert --config config-patent.yaml diagnose "특허법 PDF 폴더" --out 특허출력
```

진단 리포트(`특허출력\_reports\diagnosis-*.md`)를 보고 시작한다. 텍스트 레이어
유무, 단 수, 색 종류, 옆번호·두문자·별표 표본 수가 거기 다 있다.

## 함께 읽을 문서

| 문서 | 무엇 |
|---|---|
| `README.md` | 쓰는 법, 판단이 갈릴 수 있는 곳, 지침에서 벗어난 곳 |
| `OUTPUT.md` | **변환 결과물 규격.** 노트 단계에 반드시 함께 넘긴다 |
| `config.yaml` | 규칙 전부. 주석에 왜 그렇게 정했는지가 적혀 있다 |
