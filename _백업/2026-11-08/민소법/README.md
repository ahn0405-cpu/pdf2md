# 민사소송법 단권화

**특허법과 섞지 않는다.** 두 과목은 원본도 규칙도 결과물도 따로 간다.
공통은 `book2md/` 변환기 하나뿐이고, 그것도 설정은 과목별로 갈라져 있다
(`config-민소법.yaml` / `config-patent.yaml`).

할 일별 명령은 루트 [사용법.md](../사용법.md) 에 있다. 여기는 무엇이 어디에 있는지다.

## 무엇이 어디에

```
민소법/
├── 출력/                  ← 소스. 변환 결과 (convert all 의 산물). 손대지 않는다
│   ├── 기본서/            NN_<논점번호><제목>.md
│   └── 사례집/            <그룹>_<주제>.md        문제 지문에 진짜 사실관계가 있다
├── 노트/                  ← 결과물. 공부할 때는 여기만 연다
│   ├── 단권화/            NNN_<제목>.md           논점 단위 이해노트 (001～140)
│   ├── 목차집/            CH<장>_<제목>.md        기본서 내용·순서의 요약 (18장). 손으로 쓴다
│   ├── 암기노트/          CH<장>_<제목>.md        시험장에 들고 갈 한 권 — 답안 순서 + 압축 문장 (CH08). 손으로 쓴다
│   └── 빈칸채우기/        CH<장>_<제목>.md        암기노트의 굵은 말을 가린 연습판. 빈칸채우기.py 가 뽑는다
├── 작업/                  ← 만들고 고칠 때만
│   ├── SKILL.md           노트 작성 규칙. 이 문서가 기준이다
│   ├── 작업현황.md         어디까지 했고 무엇이 남았나
│   ├── references/        소스결함 · 확인목록(원본 대조) · 목차집·암기노트 작성 원칙
│   ├── samples/           형식 기준(046_일부청구). 규칙과 충돌하면 샘플을 우선한다
│   └── 도구/              검사·진단·수정·생성 스크립트 (목록은 루트 CLAUDE.md)
└── _보관/                 지난 스냅숏 (커밋 안 함)
```

## 노트의 네 층

뒤로 갈수록 짧아진다(2026-10-20 에 지금 모양으로 정했다).

| 문서 | 하는 일 | 순서 | 만드는 법 |
|---|---|---|---|
| 단권화 | 이해 — 판례마다 사례·판시 원문 | 기본서 | SKILL.md 대로 쓴다 |
| 목차집 | 기본서 내용과 순서의 요약 — 핵심·의의·개조식 목차·두문자 | 기본서 | 손으로 쓴다 |
| 암기노트 | 시험장에 들고 갈 한 권 — 사례집 답안 순서(단계·배점·두음) + 단계마다 압축 문장 | 답안 | 손으로 쓴다. 사례집을 보며 만든다 |
| 빈칸채우기 | 암기노트의 굵은 말을 ❶(＿＿)로 가린 연습판 | 답안 | `빈칸채우기.py` 가 뽑는다 — 손으로 고치지 않는다 |

설계 이유는 각 폴더의 README, 작성 원칙은 `작업/references/목차집.md` · `암기노트.md`.
그 전(2026-10-19～20)에는 「템플릿」(답안 뼈대)과 생성 「암기노트」(템플릿 단계에 기본서 문언·판시를 빈칸으로 붙인 것)가 따로 있었다 —
생성 암기노트가 템플릿의 3.2배가 되어 외울 수 없어서, 템플릿에 압축 문장을 더해 암기노트로 삼았다.

## 어디서 무엇을 하나

| 일 | 어디서 |
|---|---|
| PDF → 마크다운 | **원본 PDF 가 있는 PC.** `C:/Users/20090167/Documents/9. 민소법/25년 윤곽/` |
| 절 점검 | 어느 쪽이든. `convert --book 민소법 …` |
| 노트 생성·수정 | 리포를 읽는 세션. `작업/SKILL.md` 를 따른다 |

변환 결과가 바뀌면 `출력/` 을 다시 올려야 한다. 절이 바뀌면 노트의 목차도
바뀌기 때문이다. **재변환 → 올리기 → 노트** 순서를 지킨다.

## 노트를 만들기 전에 읽을 것

1. `작업/SKILL.md` — 노트 생성 규칙
2. `작업/samples/` — 형식 기준
3. `작업/작업현황.md` — 남은 일과 이미 내린 결정
4. `../book2md/OUTPUT.md` — **변환물의 한계.** 무엇을 믿고 무엇을 의심할지

기본서 ↔ 사례집 대응은 `convert mapping` 이 아니라 `작업/도구/색인.py` 로 잡는다.
`convert mapping build` 의 대응표는 확정된 것이 1건뿐이라 노트에 쓰지 않았다.
