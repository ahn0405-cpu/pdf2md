# 민사소송법 단권화

**특허법과 섞지 않는다.** 두 과목은 원본도 규칙도 결과물도 따로 간다.
공통은 `book2md/` 변환기 하나뿐이고, 그것도 설정은 과목별로 갈라져 있다
(`config-민소법.yaml` / `config-patent.yaml`).

## 무엇이 어디에

```
민소법/
├── 출력/                  ← 소스. 변환 결과 (convert all 의 산물). 손대지 않는다
│   ├── 기본서/            NN_<논점번호><제목>.md
│   └── 사례집/            <그룹>_<주제>.md
├── 노트/                  ← 결과물. 공부할 때는 여기만 연다
│   ├── 단권화/            NNN_<제목>.md        논점 단위 이해노트
│   └── 암기노트/          CH<장>_<제목>.md     빈칸 채우기. 단권화에서 뽑는다
├── 작업/                  ← 만들고 고칠 때만
│   ├── SKILL.md           노트 생성 규칙. 이 문서가 기준이다
│   ├── 작업현황.md         어디까지 했고 무엇이 남았나
│   ├── references/        소스 결함 · 원본 대조 목록
│   ├── samples/           형식 기준. 규칙과 충돌하면 샘플을 우선한다
│   └── 도구/              검사·진단·수정 스크립트 (목록은 루트 CLAUDE.md)
└── _보관/                 지난 스냅숏 (커밋 안 함)
```

## 어디서 무엇을 하나

| 일 | 어디서 |
|---|---|
| PDF → 마크다운 | **사장님 PC.** 원본 PDF가 거기 있다 |
| 절 점검·매핑 | 어느 쪽이든. `convert --book 민소법 …` |
| 노트 생성·수정 | 리포를 읽는 세션. `작업/SKILL.md` 를 따른다 |

변환 결과가 바뀌면 `출력/` 을 다시 올려야 한다. 절이 바뀌면 노트의 목차도
바뀌기 때문이다. **재변환 → 올리기 → 노트** 순서를 지킨다.

## 노트를 만들기 전에 읽을 것

1. `작업/SKILL.md` — 노트 생성 규칙
2. `작업/samples/` — 형식 기준
3. `작업/작업현황.md` — 남은 일과 이미 내린 결정
4. `../book2md/OUTPUT.md` — **변환물의 한계.** 무엇을 믿고 무엇을 의심할지

기본서 ↔ 사례집 대응은 `mapping.yaml` 이 아니라 `작업/도구/색인.py` 로 잡는다.
`convert mapping build` 가 만든 대응표(`book2md/_work/mapping.yaml`)는 확정된 것이
1건뿐이라 노트에 쓰지 않는다.
