# 특허법 작업현황

지금 하는 일은 **목차집**이다(`노트/목차집/CH<장>_<장제목>.md`). 단권화 노트는 만들지 않는다.
9개 장 115개 논점을 모두 썼다(2026-10-10). 이제는 회독하며 고칠 곳을 고치는 단계 — 아래 「미결」부터 본다.
어느 PC 에서든 이 파일부터 읽고, 작성 원칙은 `references/목차집.md` 를 따른다.

사례 줄은 제목 묶음만 믿지 말고 `목차재료.py <논점>` 의 「4 사례집」(답안 목차에 논점 이름이 나오는 문제)으로 찾는다 — 다른 장의 문제에 걸리는 일이 많다.

## 한 장을 쓰는 순서

```bash
cd 특허법/작업/도구
python3 목차재료.py 5-03                 # 1. 논점 재료 — 머리·뼈대·의의·학설·사례집에 걸린 문제, ⚠추록·⚠정오
python3 목차재료.py --문제 054-079        # 2. 사례 줄 재료 — 문제별 설문(배점)·답안 목차 전체
python3 두문자원본.py CH05                # 3. 두문자 줄을 원본 PDF 에서 잘라 그림으로 → 열어서 읽는다
python3 두문자원본.py 5-03 --찾기 판시한다  #    깨진 판시는 그 글자가 든 줄을 잘라 읽는다
python3 두문자원본.py --책 추록 --쪽 4     #    추록·정오표 원본 쪽
#                                          4. 기본서 원문(출력/기본서/NNN_*.md)을 읽고 장 파일에 손으로 쓴다
python3 목차재료.py --검사                # 5. 빠진 논점 · 기본서에 없는 두문자
#                                          6. 깨져 있던 두문자는 references/두문자확인.md 에 더하고 다시 --검사
```

- **두문자는 변환물 글자를 그대로 옮기지 않는다.** 장마다 30여 개가 OCR 로 깨져 있었다
  (CH02: 33개, CH04: 13개). 기본서 앞말의 `mnemonics:` 도 깨진 글자 그대로다(「기모자연동」 ← [기모자연통]).
- 원본 PDF 가 없는 PC 에서는 3번을 못 한다. 그때는 깨진 두문자를 **추측해 채우지 말고**
  변환물 모양 그대로 두고 `〔원본 확인 필요〕` 를 달아, 원본이 있는 PC 에서 고친다.
- 특허청(장) → 지식재산처(장)은 추록대로 일괄 적용한다(장 파일 머리에 한 번 밝힌다).
- 장 하나를 쓰면 이 표의 상태를 ○ 로 바꾸고 커밋한다.

CH01·03·05·06 을 쓰며 알게 된 것 (CH07 부터 그대로 따른다)

- **기출 회차는 변환물 머리를 믿지 않는다.** 논점 머리의 「48회 | 51회」가 변환물에서 자주 빠졌다
  (CH03 4개, CH05 8개 논점). 각 논점 첫 쪽 윗부분을 원본에서 잘라 본다. 박스 머리의 `기출문제 57(4)` 도
  변환물에서 「翻璃피57(4)」처럼 깨지므로, 박스별 기출 표시는 원본 쪽으로 확인한다.
- **판시가 OCR 로 뭉개진 곳**(「又 °)..lA7A0」 같은 줄)은 `두문자원본.py <논점> --찾기 <앞뒤 낱말>` 이나
  `--쪽 N` 으로 원본을 보고 쓴다. `--쪽` 은 해상도가 낮으니 글자가 작으면 쪽을 반으로 잘라 110~120dpi 로 본다.
- **추록·정오표는 원본 쪽을 반드시 본다.** 정오.md 의 「수정」 줄은 원본을 본 뒤 무엇이 바뀌었는지
  구체적으로 고쳐 둔다(CH05 에서 007·075·126 을 이렇게 바꿨다).
- **풀이 볼드와 두문자 글자가 다를 수 있다**(6-12 `[기표대]` — 볼드는 「다」양화). 원본 두문자대로 쓰고 한 줄 밝힌다.
- 다른 논점의 두문자를 교차참조로 적으면 `--검사` 가 「두문자?」로 띄운다 — 교차참조에는 두문자를 쓰지 않는다.
- 사례 줄은 제목 묶음 밖에서도 찾는다: `목차재료.py <논점> --키 낱말…` 로 걸린 문제를 모으고
  `--문제 NNN-NNN` 출력을 한 파일로 떨궈 읽는다. 배점이 비면 사례집 원문에서 `(N점)` 을 grep 한다.
- 장 하나에 두문자 30~40개를 두문자확인.md 에 올린다(변환물 모양·PDF 쪽과 함께).

CH07 을 쓰며 더 알게 된 것

- **`두문자원본.py CH07` 의 두문자 줄 목록이 전부가 아니다.** 변환물에 대괄호가 안 찍힌 두문자는 빠진다
  (7-05 `[심적공유공]`). 기본서 원문을 읽다가 `==십==판의 ==적==정…` 처럼 볼드가 연달아 있으면 그 줄을 원본에서 잘라 본다.
- **정오.md 의 「추가/삭제」 방향도 원본으로 확인한다.** 011 은 「공유」가 빨간 취소선(삭제)인데 「공유 특허권자로」라고
  반대로 적혀 있었다(CH07 에서 고침). 정오표 원본은 `--책 정오표 --쪽 N` 으로 보고, 색이 작으면 그 줄만 200dpi 로 자른다.
- **사례집 설문 배점이 변환물에 아예 없는 문제가 있다**(128(2) — 원본은 16점). 변환물 grep 으로 안 나오면
  사례집 원본 PDF 에서 설문 문장을 검색해 그 쪽을 잘라 본다.
- 사례집 답안이 `>` 인용문으로 섞여 변환된 문제(124 · 126 · 128 · 148)는 `--문제` 출력에 답안 목차가 거의 안 나온다 —
  변환물에서 `> N.` `> (N)` 머리만 grep 해 목차를 잡는다.
- 파이썬으로 references 파일을 다시 쓸 때 `Path.write_text` 는 Windows 에서 CRLF 를 넣는다 — `newline="\n"` 을 주거나 끝나고 `file` 로 확인한다.

## 준비 (새 PC)

1. `git pull` — 브랜치 `claude/pdf-to-markdown-converter-lvkvkr`
2. `pip install PyMuPDF` — 두문자원본.py 에 필요하다(목차재료.py 는 없어도 된다)
3. 원본 PDF 위치 — 기본은 사장님 PC 의 `F:\GoogleDrive\00-안-개인\…`(경로.py 의 `_원본`).
   다르면 환경변수 `TEMA_PDF_DIR` 에 PDF 가 든 폴더를 준다(파일 하나씩은 `TEMA_TEXTBOOK` ·
   `TEMA_CASEBOOK` · `TEMA_ADDENDUM` · `TEMA_ERRATA`). 폴더로 줄 때 파일 이름은
   `테마 특허법.pdf` · `테마 특허법 사례집.pdf` · `[A4_양면_한쪽]_박지환T_테마특허법_9판_1차추록(특강).pdf` ·
   `테마 사례집_5판_정오표.pdf` (사례집은 `특허_테마_사례_압축.pdf` 도 된다 — 쪽 배치가 같다)
