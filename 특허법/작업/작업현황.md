# 특허법 작업현황

지금 하는 일은 **목차집**이다(`노트/목차집/CH<장>_<장제목>.md`). 단권화 노트는 만들지 않는다.
어느 PC 에서든 이 파일부터 읽고, 작성 원칙은 `references/목차집.md` 를 따른다.

사례 줄은 제목 묶음만 믿지 말고 `목차재료.py <논점>` 의 「4 사례집」(답안 목차에 논점 이름이 나오는 문제)으로 찾는다 — 다른 장의 문제에 걸리는 일이 많다.

## 한 장을 쓰는 순서

```bash
cd 특허법/작업/도구
python3 목차재료.py 5-03                 # 1. 논점 재료 — 머리·뼈대·의의·학설·사례집에 걸린 문제, ⚠추록·⚠정오
python3 목차재료.py --문제 054-079        # 2. 사례 줄 재료 — 문제별 설문(배점)·답안 목차 전체
python3 두문자원본.py CH05                # 3. 두문자 줄을 원본 PDF 에서 잘라 그림으로 → 열어서 읽는다
python3 두문자원본.py 5-03 --찾기 판시한다  #    깨진 판시는 그 글자가 든 줄을 잘라 읽는다
python3 두문자원본.py --책 추록 --쪽 4     #    추록·정오표 원본 쪽
#                                          4. 기본서 원문(출력/기본서/NNN_*.md)을 읽고 장 파일에 손으로 쓴다
python3 목차재료.py --검사                # 5. 빠진 논점 · 기본서에 없는 두문자
#                                          6. 깨져 있던 두문자는 references/두문자확인.md 에 더하고 다시 --검사
```

- **두문자는 변환물 글자를 그대로 옮기지 않는다.** 장마다 30여 개가 OCR 로 깨져 있었다
  (CH02: 33개, CH04: 13개). 기본서 앞말의 `mnemonics:` 도 깨진 글자 그대로다(「기모자연동」 ← [기모자연통]).
- 원본 PDF 가 없는 PC 에서는 3번을 못 한다. 그때는 깨진 두문자를 **추측해 채우지 말고**
  변환물 모양 그대로 두고 `〔원본 확인 필요〕` 를 달아, 원본이 있는 PC 에서 고친다.
- 특허청(장) → 지식재산처(장)은 추록대로 일괄 적용한다(장 파일 머리에 한 번 밝힌다).
- 장 하나를 쓰면 이 표의 상태를 ○ 로 바꾸고 커밋한다.

## 준비 (새 PC)

1. `git pull` — 브랜치 `claude/pdf-to-markdown-converter-lvkvkr`
2. `pip install PyMuPDF` — 두문자원본.py 에 필요하다(목차재료.py 는 없어도 된다)
3. 원본 PDF 위치 — 기본은 사장님 PC 의 `F:\GoogleDrive\00-안-개인\…`(경로.py 의 `_원본`).
   다르면 환경변수 `TEMA_PDF_DIR` 에 PDF 가 든 폴더를 준다(파일 하나씩은 `TEMA_TEXTBOOK` ·
   `TEMA_CASEBOOK` · `TEMA_ADDENDUM` · `TEMA_ERRATA`). 폴더로 줄 때 파일 이름은
   `테마 특허법.pdf` · `테마 특허법 사례집.pdf` · `[A4_양면_한쪽]_박지환T_테마특허법_9판_1차추록(특강).pdf` ·
   `테마 사례집_5판_정오표.pdf` (사례집은 `특허_테마_사례_압축.pdf` 도 된다 — 쪽 배치가 같다)
