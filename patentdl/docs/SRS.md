## 1. 개요

### 1.1 목적

특허번호를 **직접 입력**하거나, 특허 공보의 **인용/피인용 표 화면을 캡처한 그림을 붙여넣으면**,
그 안의 공보번호를 자동으로 인식해 [Google Patents](https://patents.google.com)에서
**해당 특허 PDF를 일괄 내려받는** 웹 프로그램을 만든다.

해결하려는 불편은 이것이다. 심사·조사 실무에서 인용문헌 표에 있는 5~30건을 확인하려면
번호를 하나씩 손으로 옮겨 적어 검색하고 PDF를 하나씩 저장해야 한다.
표를 캡처해 던지면 ZIP 하나로 끝나게 한다.

### 1.2 범위

**포함**

- 특허번호 텍스트 입력(여러 건, 자유 서식) → 정규화 → PDF 다운로드
- 표 캡처 이미지 입력(붙여넣기/드래그) → OCR → 공보번호 추출 → 다운로드
- 인식 결과를 **내려받기 전에 사용자가 확인·수정**하는 화면
- 개별 저장 / 전체 ZIP / 메타데이터(CSV·JSON) 저장
- 서지 정보(발명의 명칭, 출원인, 공개·등록일, IPC/CPC) 조회 및 파일명 반영

**제외 (v1 기준)**

- Google Patents 전문 검색(키워드 검색), 패밀리 전체 수집, 인용망 재귀 추적
- KIPRIS·EPO OPS·USPTO 등 타 DB 직접 연동 (2차 후보로만 검토 — 6장)
- 로그인이 필요한 유료 DB, 번역 기능, 다운로드한 PDF의 내용 분석
- 다중 사용자 계정·권한 관리 (개인 도구로 설계)

### 1.3 용어

| 용어 | 뜻 |
|---|---|
| 공보번호 | 공개공보/등록공보에 부여된 번호. 예 `10-2012-0078027`, `US 2007/0258188` |
| 문서 ID | Google Patents가 쓰는 정규 식별자. `KR20120078027A`, `US20070258188A1` 형태 |
| 종류코드(kind code) | 문서 종류를 뜻하는 접미 기호. `A`(공개), `B1/B2`(등록), `U`(실용신안) 등 |
| 정규화 | 사람이 쓴 여러 표기를 문서 ID 하나로 바꾸는 것 |
| 해석(resolve) | 문서 ID로 Google Patents에서 실제 PDF 주소와 서지를 얻는 것 |
| 작업(job) | 번호 1건에 대한 조회~다운로드 단위 |

### 1.4 참고

- Google Patents 특허 상세 페이지: `https://patents.google.com/patent/{문서ID}/{언어}`
- PDF 저장소: `https://patentimages.storage.googleapis.com/...`
- 같은 저장소의 기존 프로젝트 `pdf2md` (브라우저 단독 PDF→Markdown 변환기) — 8장 연계

## 2. 전체 설명

### 2.1 제품 조망

**웹페이지 방식**이되, 기존 `pdf2md`처럼 브라우저 파일 하나로는 만들 수 없다.
`patents.google.com`은 브라우저의 교차출처(CORS) 요청을 허용하지 않으므로,
페이지 자바스크립트가 직접 특허 페이지를 읽어올 수 없다.
따라서 **아주 얇은 로컬 서버 + 브라우저 UI** 구조로 간다.

```
[브라우저 UI]                        [로컬 서버 (Node)]                [외부]
 번호 입력 ─┐
 이미지 붙여넣기 ─ OCR(브라우저 내) ─┐
                                     ├─ /api/resolve ──▶ patents.google.com (HTML 파싱)
 확인 화면 ◀── 정규화 결과 ───────────┤
 다운로드 ────────────────────────────┴─ /api/pdf ─────▶ patentimages.storage.googleapis.com
 ZIP 묶기(브라우저 내)                    캐시(디스크)
```

설계 원칙 세 가지.

1. **OCR은 브라우저에서** 한다. 캡처 이미지가 서버로 나가지 않는다(사내 자료 캡처를 고려).
2. **서버는 중계만** 한다. 상태를 거의 갖지 않고, 캐시 외에 사용자 데이터를 남기지 않는다.
3. **자동 다운로드 전에 사람이 한 번 본다.** OCR은 틀릴 수 있으므로 확인 단계를 필수로 둔다.

### 2.2 사용자와 사용 상황

| 사용자 | 상황 | 기대 |
|---|---|---|
| 특허 실무자(주 사용자) | 심사·무효조사 중 인용문헌 표를 만남 | 표를 캡처해 던지면 전건 PDF가 ZIP으로 |
| 연구자 | 특정 번호 몇 건을 확인 | 번호를 줄바꿈으로 붙여넣고 즉시 다운로드 |
| 재사용 | 같은 번호를 다시 요청 | 캐시로 즉시 응답 |

### 2.3 제약

| 구분 | 제약 |
|---|---|
| 기술 | 브라우저에서 구글특허 직접 호출 불가(CORS) → 로컬 서버 필수 |
| 기술 | 구글특허는 공개 API가 아니다. HTML 구조가 바뀌면 파서가 깨진다 → 파싱 규칙 격리·자동 감시 필요 |
| 예의/준법 | 과도한 요청 금지. 동시 요청 상한과 요청 간 간격을 코드로 강제한다 |
| 자료 | 특허 공보는 공개 문서이나, 문서마다 PDF가 없을 수 있다(특히 일부 국가·구형 문서) |
| 개발 환경 | 현재 원격 개발 컨테이너는 `patents.google.com` 접속이 정책상 차단됨 → 실통신 검증은 로컬에서 (7장) |

### 2.4 가정 및 의존

- (A1) 특허 상세 HTML에 PDF 직링크가 메타 태그로 노출된다. **미검증 — 7.1의 기술검증에서 최우선 확인.**
- (A2) 문서 ID에 종류코드가 없으면 페이지를 못 찾을 수 있다 → 후보 종류코드를 순서대로 시도한다(FR-3.4).
- (A3) 사용자는 Node 20 이상을 설치할 수 있다. 아니면 단일 실행파일 배포로 대체(6장 Q3).

## 3. 외부 인터페이스

### 3.1 화면 (한 페이지, 3단 흐름)

**① 입력부**

- 큰 텍스트 영역: 번호를 줄바꿈·쉼표·공백 아무렇게나 붙여넣어도 된다.
- 같은 영역에 **이미지 붙여넣기(Ctrl+V)**, 드래그&드롭, 파일 선택(PNG/JPG/WebP) 지원.
- 캡처 화면 자체를 그대로 붙여넣는 것이 주 사용 방식이다(첨부 예시: 인용 표).
- 옵션: 언어(en/ko), 파일명 규칙, 메타데이터 동시 저장, 없는 PDF 처리 방식.

**② 확인부 (핵심 화면)**

인식 결과를 표로 보여준다. 여기서 고치지 않으면 다운로드가 시작되지 않는다.

| 선택 | 인식 원문 | 문서 ID | 국가 | 종류 | 신뢰도 | 상태 |
|---|---|---|---|---|---|---|
| ☑ | `1020120078027 A` | `KR20120078027A` | KR | 공개 | 높음 | 확인됨 |
| ☑ | `20070258188 A1` | `US20070258188A1` | US | 공개 | 높음 | 확인됨 |
| ☐ | `1O2562600OOOO B1` | `KR102562600B1` | KR | 등록 | **낮음(O/0 교정)** | 검토 필요 |

- 신뢰도가 낮거나 종류코드를 추정한 행은 노란색으로 강조하고 기본 선택을 해제한다.
- 문서 ID 칸은 직접 편집할 수 있고, 편집하면 즉시 재검증한다.
- 원본 이미지에서 그 숫자가 어디였는지 **해당 영역을 되짚어 보여준다**(오인식 판단용).

**③ 진행·결과부**

- 건별 진행 상태(대기/조회중/내려받는중/완료/실패)와 사유.
- 완료분 개별 저장 ⬇, **전체 ZIP**, 메타데이터 CSV/JSON 저장.
- 실패분만 재시도.

### 3.2 서버 API

| 메서드 | 경로 | 요청 | 응답 |
|---|---|---|---|
| POST | `/api/resolve` | `{ids:["KR20120078027A", ...], lang:"ko"}` | 건별 `{id, resolvedId, title, assignee, date, ipc[], pdfUrl, status}` |
| GET | `/api/pdf?id={문서ID}` | — | `application/pdf` 스트림 (없으면 404 + 사유 JSON) |
| GET | `/api/health` | — | `{ok, version, cacheCount}` |

- 모든 응답은 건별로 `status`(`ok` / `not_found` / `no_pdf` / `blocked` / `error`)와 사람이 읽는 `message`를 담는다.
- 서버는 `127.0.0.1`에만 바인딩한다(기본값). 외부 노출은 명시적 옵션으로만.

### 3.3 외부 시스템

| 대상 | 용도 | 실패 시 |
|---|---|---|
| `patents.google.com/patent/{ID}/{lang}` | 서지 + PDF 주소 | 재시도 → 실패 표시 |
| `patentimages.storage.googleapis.com` | PDF 본문 | 재시도 → 실패 표시 |

## 4. 기능 요구사항

우선순위 — **M**(필수, v1) / **S**(있으면 좋음) / **C**(추후).

### FR-1 번호 텍스트 입력 (M)

- FR-1.1 (M) 줄바꿈·쉼표·세미콜론·공백으로 구분된 여러 건을 한 번에 받는다.
- FR-1.2 (M) `제10-2012-0078027호`, `KR 10-2012-0078027 A`, `US 2007/0258188 A1`,
  `US7,123,456`, `WO 2020/123456`, `EP 1 234 567 B1` 같은 표기를 모두 받아들인다.
- FR-1.3 (M) 중복은 하나로 합치고, 합쳐진 건수를 표시한다.
- FR-1.4 (S) 붙여넣은 문장 속에 섞인 번호도 골라낸다(문장 전체를 붙여넣어도 됨).

### FR-2 이미지 입력과 인식 (M) — 이 프로그램의 차별점

- FR-2.1 (M) 클립보드 붙여넣기, 드래그&드롭, 파일 선택으로 이미지를 받는다.
- FR-2.2 (M) 브라우저 내 OCR(한국어+영어)로 글자와 **글자 위치 상자**를 얻는다.
- FR-2.3 (M) 위치의 세로 좌표로 **행을, 가로 좌표로 열을 복원**해 표 구조를 되살린다.
  첨부 예시의 `국가 | 공보번호 | 공보일자 | 발명의 명칭 | IPC` 5열 구조가 그대로 살아나야 한다.
- FR-2.4 (M) 같은 행의 **국가 칸**(`미국`, `대한민국`, `일본`, `유럽`, `중국`, `국제`)을 읽어
  번호 해석의 국가 힌트로 쓴다. 국가 칸이 없으면 번호 길이·형태로 추정한다.
- FR-2.5 (M) 셀 안에서 줄바꿈된 번호(`10201200780` + `27 A`)를 한 번호로 다시 잇는다.
  예시 그림처럼 좁은 칸에서 번호가 두 줄로 접히는 것이 흔하다.
- FR-2.6 (M) OCR 혼동 문자를 국가별 형식에 맞춰 교정한다: `O↔0`, `I/l↔1`, `S↔5`, `B↔8`, `Z↔2`.
  **교정한 건은 신뢰도를 낮춤으로 표시**하고 기본 선택을 해제한다(FR-4.2).
- FR-2.7 (S) `인용` / `피인용` 제목을 인식해 각 건에 구분을 붙이고, 파일명·메타에 남긴다.
- FR-2.8 (S) 이미지 여러 장을 한 번에 받는다(표가 여러 화면으로 잘린 경우).
- FR-2.9 (C) 화면 캡처 대신 PDF 공보의 인용 페이지를 직접 받는다(pdf2md 엔진 재사용, 8장).

### FR-3 번호 정규화 (M) — 정확도의 핵심

입력 표기를 Google Patents 문서 ID로 바꾼다.

| 국가 | 입력 예 | 규칙 | 문서 ID |
|---|---|---|---|
| KR 공개 | `1020120078027 A`, `10-2012-0078027` | `10` + 연도4 + 일련7 → `KR`+연도+일련+`A` | `KR20120078027A` |
| KR 등록 | `1025626000000 B1`, `10-2562600` | `10`+일련7(+`0000`) → `KR10`+일련7+`B1` | `KR102562600B1` |
| KR 구등록 | `10-0123456` | 6자리 일련도 허용 | `KR100123456B1` |
| KR 실용 | `20-2012-0001234` | 접두 `20` → `KR`+…+`U` | `KR20120001234U` |
| US 공개 | `2007/0258188 A1`, `20070258188` | 11자리 = 연도4+일련7 | `US20070258188A1` |
| US 등록 | `7,123,456 B2`, `7123456` | 7~8자리 | `US7123456B2` |
| EP | `EP 1 234 567 B1` | 공백 제거 | `EP1234567B1` |
| WO | `WO 2020/123456` | | `WO2020123456A1` |
| JP | `특개2020-123456`, `JP2020-123456A` | 연호 표기(`평11`→`H11`) 포함 | `JP2020123456A` |
| CN | `CN 101234567 A` | | `CN101234567A` |

- FR-3.1 (M) 위 표의 국가별 규칙을 구현하고, **규칙표 자체를 데이터로 분리**해 국가를 늘리기 쉽게 한다.
- FR-3.2 (M) KR 13자리에서 **공개(연도형)와 등록(일련형)을 구분**한다.
  판별 기준: 3~6번째 자리가 유효 연도(1948~현재+1)이고 뒷자리가 `0000`이 아니면 공개,
  뒤 4자리가 `0000`이면 등록으로 본다. 양쪽 모두 가능하면 두 후보를 모두 시도한다(FR-3.4).
- FR-3.3 (M) 국가 접두가 없고 국가 힌트도 없으면 자릿수로 추정하되 신뢰도를 낮춤으로 둔다.
- FR-3.4 (M) 종류코드가 없거나 불확실하면 후보를 순서대로 조회해 처음 성공한 것을 쓴다
  (KR: `B1`→`A`→`B`, US: `B2`→`B1`→`A1`). 시도 횟수는 건당 3회로 제한한다.
- FR-3.5 (M) 어떤 규칙으로도 해석되지 않으면 버리지 않고 **"해석 실패"로 표에 남겨** 사용자가 고치게 한다.
- FR-3.6 (M) 정규화 로직은 네트워크 없이 순수 함수로 동작해 단위테스트가 가능해야 한다.

### FR-4 확인 단계 (M)

- FR-4.1 (M) 해석 결과 전체를 표로 보여주고, 사용자가 **선택·수정한 뒤에만** 다운로드가 시작된다.
- FR-4.2 (M) 신뢰도 낮음(문자 교정·종류코드 추정·국가 추정)은 강조 + 기본 선택 해제.
- FR-4.3 (M) 문서 ID 직접 수정 가능. 수정 시 즉시 형식 검증.
- FR-4.4 (S) 각 행에서 원본 이미지의 해당 영역을 확대해 보여준다.
- FR-4.5 (S) 확인 화면에서 서지(명칭·출원인·일자)를 미리 조회해 **엉뚱한 특허인지 눈으로 거른다.**

### FR-5 조회와 다운로드 (M)

- FR-5.1 (M) 문서 ID로 서지(명칭, 출원인/양수인, 공개·등록일, IPC/CPC)와 PDF 주소를 얻는다.
- FR-5.2 (M) PDF를 내려받아 브라우저에 전달한다. 진행률을 건별로 표시한다.
- FR-5.3 (M) 동시 요청은 **최대 3건**, 요청 사이 최소 300ms 간격을 강제한다.
- FR-5.4 (M) 실패 시 지수 백오프로 최대 3회 재시도(2s→4s→8s). 429/503은 더 길게 쉰다.
- FR-5.5 (M) 한 건의 실패가 나머지를 멈추지 않는다.
- FR-5.6 (M) 취소 버튼으로 진행 중 작업을 중단할 수 있다.
- FR-5.7 (S) 같은 문서 ID는 디스크 캐시에서 재사용한다(기본 7일, 설정 가능).
- FR-5.8 (M) PDF가 제공되지 않는 문서는 사유(`no_pdf`)를 명확히 표시하고, 서지만이라도 남긴다.

### FR-6 저장 (M)

- FR-6.1 (M) 개별 저장, 전체 ZIP 저장.
- FR-6.2 (M) 파일명 규칙(기본): `{문서ID}_{발명의명칭 30자}.pdf`
  → `KR20120078027A_배터리와 슈퍼커패시터를 병용하는 하이브리드.pdf`
  파일명 금지문자는 `_`로, 길이는 안전하게 자른다(윈도우 260자 고려).
- FR-6.3 (S) 파일명 규칙을 사용자가 바꿀 수 있다(`{국가}{번호}`, `{일자}_{ID}` 등 토큰 조합).
- FR-6.4 (M) 메타데이터를 CSV(엑셀 한글 깨짐 방지 BOM 포함)와 JSON으로 저장한다.
  열: 인식원문, 문서ID, 국가, 종류, 명칭, 출원인, 공개일, 등록일, IPC, 인용구분, PDF유무, 실패사유.
- FR-6.5 (S) 옵션은 브라우저에 저장되어 다음에 열 때 그대로 쓰인다(pdf2md와 동일한 방식).

### FR-7 오류 처리 (M)

| 상황 | 사용자에게 보이는 것 | 프로그램 동작 |
|---|---|---|
| 번호 해석 실패 | "번호 형식을 알 수 없다. 직접 고쳐 달라" | 행 유지, 수정 대기 |
| 문서 없음(404) | "구글특허에 해당 문서가 없다" + 다른 종류코드 제안 | 후보 종류코드 자동 시도 후 중단 |
| PDF 미제공 | "이 문서는 PDF가 제공되지 않는다" + 특허 페이지 링크 | 서지만 저장 |
| 요청 과다(429) | "잠시 쉬고 다시 시도한다" + 남은 대기 시간 | 자동 백오프 |
| 네트워크 차단 | "구글특허에 접속할 수 없다. 네트워크·방화벽 확인" | 전체 중단, 원인 안내 |
| 페이지 구조 변경 | "구글특허 화면이 바뀌어 정보를 읽지 못했다" | 진단용 원문 저장 옵션 |

## 7. 검증 계획

### 7.1 기술검증(spike) — 착수 전 3가지를 먼저 확인한다

1. **PDF 주소 획득 경로** — 특허 상세 HTML에서 PDF 직링크를 안정적으로 얻을 수 있는가.
   메타 태그가 없으면 대안(내부 조회 응답, 헤드리스 브라우저 렌더)을 순서대로 검증한다.
   가정 A1이 전부 깨지면 아키텍처가 바뀐다. **가장 먼저 한다.**
2. **KR 문서의 PDF 제공률** — 예시 표의 KR 3건이 실제로 PDF를 주는지 확인. 낮으면 Q4가 필수가 된다.
3. **OCR 실측** — 첨부 예시 캡처를 그대로 넣어 공보번호 5건 인식률 측정.

> 주의: 현재 원격 개발 컨테이너는 `patents.google.com` 접속이 정책상 차단되어 있다(403).
> 위 1·2번 검증과 통합 테스트는 **접속이 되는 로컬 환경**에서 수행한다.
> 저장소의 자동 테스트는 네트워크 없이 도는 것(정규화·표 복원·파일명)만 CI에 넣는다.

### 7.2 수용 기준

| # | 시나리오 | 통과 조건 |
|---|---|---|
| AC-1 | 첨부된 인용 표 캡처를 붙여넣는다 | 3건(`KR20120078027A`, `US20070258188A1`, `KR102562600B1`)이 모두 확인 화면에 뜨고, 두 줄로 접힌 번호가 하나로 이어져 있다 |
| AC-2 | 확인 후 전체 다운로드 | PDF가 제공되는 건은 모두 저장되고, ZIP 파일명이 규칙과 일치한다 |
| AC-3 | 번호 10건을 줄바꿈으로 붙여넣기 | 60초 내 완료, 실패 건은 사유가 표시된다 |
| AC-4 | OCR이 `0`을 `O`로 잘못 읽음 | 자동 교정되고 "낮음"으로 표시되며 기본 선택이 해제된다 |
| AC-5 | 존재하지 않는 번호 포함 | 그 건만 실패, 나머지는 정상 완료 |
| AC-6 | 네트워크 차단 상태에서 실행 | 접속 불가 사유가 명확히 표시되고 프로그램이 죽지 않는다 |
| AC-7 | 동일 번호 재요청 | 캐시에서 즉시 응답(외부 요청 0회) |

### 7.3 테스트 자산

- 정규화 단위테스트: 국가별 표기 60종 이상의 입력/기대 문서 ID 쌍(네트워크 불필요)
- 표 복원 단위테스트: OCR 단어 상자 좌표 고정 데이터 → 기대 행/열
- 통합 테스트: 외부 응답을 녹화한 고정 데이터(fixture)로 대체 실행

## 8. 기존 `pdf2md`와의 관계

같은 사용자·같은 업무 흐름을 쓰지만 성격이 다르다.

| | pdf2md | 특허 다운로더 |
|---|---|---|
| 실행 | 파일 하나, 서버 없음 | 로컬 서버 필요(CORS 때문) |
| 네트워크 | 아예 안 씀(그게 장점) | 외부 조회가 본질 |
| 재사용 가능한 것 | UI 구성, 진행 표시, ZIP 묶기, 옵션 저장 방식 | — |

→ **저장소를 분리**하고(Q1), UI 부품과 ZIP 코드만 옮겨 쓴다.
장래에 "내려받은 공보를 바로 Markdown으로"(Q5)를 붙이면 두 도구가 한 흐름이 된다.

## 부록 A. 첨부 예시로 본 처리 과정

입력(캡처 이미지의 인용 표) → 기대 결과:

| 국가 칸 | OCR 원문(줄바꿈 포함) | 판정 | 문서 ID |
|---|---|---|---|
| 미국 | `2007025818` / `8 A1` | 11자리 + 미국 → 공개 | `US20070258188A1` |
| 대한민국 | `10201200780` / `27 A` | 13자리, 3~6자리 `2012`=연도 → 공개 | `KR20120078027A` |
| 대한민국 | `10256260000` / `00 B1` | 13자리, 뒤 4자리 `0000` → 등록 | `KR102562600B1` |

세 건 모두 셀 안에서 줄바꿈되어 있고(FR-2.5), 국가 칸이 해석의 근거가 되며(FR-2.4),
KR 두 건은 자릿수가 같지만 공개/등록이 갈린다(FR-3.2). 이 표가 M4의 통과 기준이다.
